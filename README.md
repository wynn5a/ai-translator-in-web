# AI 划词翻译（Chrome MV3）

选中文字或悬停段落后按一下 <kbd>Ctrl</kbd>，用任意 OpenAI 兼容模型翻译。

## 功能

### 翻译

- **划词翻译**：选中文字 → 按 <kbd>Ctrl</kbd> → 选区旁弹出译文气泡（Shadow DOM 隔离，不受页面样式影响）。气泡里的译文**可以直接选中复制**，点气泡外面或按 <kbd>Esc</kbd> 才关闭。
- **按语境查词**：选中的若是 5 个词以内的词/短语，会自动带上它**所在的那一句**一起发给模型，只返回该词在此语境下的释义（如 river *bank* → 河岸，而不是银行）。同一个词在段落里出现多次也能定位到正确的句子。
- **单词发音**：查词气泡（5 个词以内的词/短语）的译文**末尾跟着一个喇叭图标**（内联 SVG，与文字同一行，不额外占一行），点它朗读**原文**，用 Google 翻译的发音接口，不需要额外配置。音频在扩展的 offscreen 文档里播放，绕开宿主页面的 `media-src` CSP（GitHub、Jira 这类站点会把内容脚本里的媒体加载全拦掉）；播完 10 秒关掉文档，不长期吊住 Service Worker。发音失败只把这个按钮变红并把原因写进它的 `title`，气泡里的译文不受影响。
- **段落翻译**：不选中任何文字，鼠标悬停在段落上 → 按 <kbd>Ctrl</kbd> → 在原段落下方插入译文；再按一次收起（同时立即中止未完成的请求）。译文节点**渲染样式与原文完全一致**：复制原段落的标签和全部属性（`id` 和行内事件除外），让页面 CSS 用同样的规则命中它，本身不附加任何样式；换行用 `<br>` 还原而不是改 `white-space`。列表项 `<li>` 和表格单元格 `<td>/<th>` 的译文插在元素**内部**，不会打乱 `<ol>` 的编号或表格的列结构。
- **保留分段与行内结构**：段落里的链接、加粗、行内代码不会被拍平，原文分几段译文就分几段。块级子元素编码成 `<b1>…</b1>`、换行编码成 `<n1/>`、行内元素编码成 `<t1>…</t1>`、代码和图片编码成 `<x1/>` 送给模型，回来再套回真实节点——译文里的链接照样可点、`href`/`class` 原样保留，`<code>`、`<pre>`、`<kbd>` 里的内容原样搬回不参与翻译。单个纯文本段落不带任何标记，没有额外开销。分段一律走标记而不是裸换行——裸换行模型说合就合，标记有编号也有数量约束；模型把标记写歪（换成 `<br>`、漏斜杠、多个尖括号、大小写不对）时自动归一，漏掉或编号乱编时退化为换行或纯文本，文字和分段都不会丢。
- **代码不译**：`<pre>` 不再算可翻译段落，嵌在段落里的 `<code>`、命令、标识符作为不可翻译片段整体保护；输入框和可编辑区也不触发。
- **超长段落先确认并分片**：超过 2000 字的段落会先提示字数，点「继续翻译」才发请求。真正翻译时按句子和段落边界切成 1400 字左右的分片**串行**发送（切点绝不落在占位标记内部），后一片带上前一片译文的结尾以保证术语、人称和语气连贯——整段直发容易漏译、后半段质量下滑，还可能撞上端点的输出上限被截断。
- **流式输出**：译文边生成边显示，一帧只重绘最新的一份（模型每几个字就来一条消息，逐条重建 DOM 跟不上）。气泡的展开方向在第一帧就定好，内容变长也不会来回跳动。
- **气泡跟随滚动**：滚动页面时气泡跟着选区移动而不是消失；选区滚出视口只是暂时隐藏，翻译不会中断。
- 只有识别出的语种与目标语言**相同**时才跳过（目标语言设成 `English` 时中文照样翻译）；跳过时会有一句一闪而过的提示，不会毫无反应。

### 翻译质量

- **带上页面背景**：每次请求都附上**站点域名、页面标题、`meta description`**（各自截断），模型因此知道这段文字属于什么领域，术语不会跑偏——同一个 `pitch` 在棒球站是「投球」、在创投站是「路演」、在音频站是「音高」。
- **跨段落术语表**：按「站点 + 目标语言」维护一张术语表，翻译时把**原文里真的出现了**的条目作为「已确定的译法」注入提示词，同一个词在整站每一段里都译成同一个样子。三个来源：
  - **查词结果**——选中一个词得到的释义本身就是一条对照，不额外花钱；
  - **短译文**——标题、表头、按钮、链接文字这类整块就是一个词组的译文，直接入表，不额外花钱；
  - **术语抽取**——长段落（≥120 字）译完后，再用一次很短的请求从原文/译文里抽最多 6 条术语。这一步在**译文已经显示给用户之后**才发起，不占用户等待时间，可以在设置页「高级」里关掉。
  
  注入时长术语优先、单次最多 12 条，所以提示词开销与段落内容成正比而不是与表的大小成正比。拉丁词按**词边界**匹配（`AI` 不会在 `said` 里命中），中日韩按子串。模型抽出的词若不在原文里出现会被丢弃，避免把幻觉写进表。每站最多 80 条、最多 30 个站点，按最近使用淘汰，落盘存 `__glossary`。
- **分档提示词**：查词 / 划词 / 段落三种任务各有一套「角色 + 页面背景 + 编号规则 + 输出约束」的提示词。硬规则包括：不增不减不加译者注、数字与单位与代码与 URL 原样保留、专有名词不音译、术语用该领域通行译法、保持原文语域和语气、已是目标语言的片段原样输出。
- **划词与查词分开**：选中一个词/短语时按「词典」处理（给该语境下的确切义项，词性跟着原词）；选中一句话时按「片段」处理（明确告知可能不是完整句子，不要补全扩写）。
- **温度分档**：查词 `0`（要唯一解）、划词 `0.2`、段落 `0.3`（要通顺）。
- **标记丢了自动补一次**：带结构标记的段落译完后核对标记多重集（写歪的归一后再比），模型漏了哪几个就点名重发一次（温度 0），两份里取丢得少的。正常情况不多花一个请求，小模型丢链接、并段的概率明显下降。
- **思考过程不当译文**：「关闭思考」参数被端点拒绝后，Qwen3 / DeepSeek-R1 这类模型会把推理写在 `<think>…</think>` 里混进正文；这一块连同流式中还没闭合的半截一律去掉。
- **输出上限保护**：按源文长度自动下发 `max_tokens`（`o1`–`o9` / `gpt-5` 系用 `max_completion_tokens`），长段落不会被端点的默认上限悄悄截断。
- **请求参数三档降级**：全量（调参 + 关闭思考 + 额外参数）→ 只留调参 → 一个不带。返回 400 就降一档重试并记住该端点，因此 `o` 系拒绝 `temperature`、部分中转站拒绝一切未知字段时都能自动谈成。

### 多套配置（Profile）

- 每个 profile 是一整套 AI 配置：**接口地址 + 密钥 + 模型 + 目标语言 + 关闭思考 + 额外请求参数**。想按场景分开（便宜模型日常用 / 强模型啃长难句 / 本地模型离线用 / 英译中和中译英各一套）建几套就行。
- **切换即生效**：在弹窗顶部的下拉框里选一个，立刻写入存储，下一次翻译就走新配置，不用点保存、不用刷新页面（已打开的标签页也会实时跟上）。
- 切换前会自动把当前表单里的改动存回原 profile，改一半切走不会丢。
- **＋** 复制当前配置新建一套（密钥一并带过来，只改模型很方便），**−** 删除当前配置（点两次确认，只剩一套时不可删）。改「配置名称」就是重命名。
- 触发键和按站点停用是**全局**的，不随 profile 变——设置页里用一条分隔线标出。
- 译文缓存按「接口地址 + 模型 + 目标语言 + 任务类型 + 站点与页面标题」区分，切了 profile 不会拿到上一套的译文；页面标题进了提示词，所以也参与缓存键。

### 触发

- 触发键为「单独按下并松开」，`Ctrl+C` 等组合键、<kbd>Ctrl</kbd>+滚轮缩放、按住超过 1.2 秒都不会误触发。
- 按住触发键时，**将被翻译的段落会高亮描边**，松手前就知道会翻译哪一块。
- 按了热键但鼠标底下没有可翻译的段落时，会有一句一闪而过的提示，不会毫无反应——「按了没动静」到底是没触发还是触发了看不见，最难排查。
- 右键菜单也提供「翻译选中文字 / 翻译此段落」，不方便用热键时可用。
- **兼容页面自带的划词菜单**：这类菜单常把选区收走（focus 到隐藏输入框、`removeAllRanges()`、在选区里插节点），也常在 `window` 捕获阶段掐断按键。为此内容脚本在 `document_start` 就注册监听（早于页面脚本，`stopImmediatePropagation` 掐不掉），并在页面处理之前记下最近一次有效选区；选区节点被替换时退化为「按缓存文本翻译 + 气泡锚在鼠标处」。下一次点击即作废缓存，不会误译上一段选中的内容。
- 支持 iframe 内的页面。
- 可以**按站点停用**：点工具栏图标，取消勾选「在 xxx 上启用」。

### 稳定性

- **译文缓存落盘**：Service Worker 休眠后缓存依然有效（最多 300 条，LRU 淘汰），不会重复计费。术语表同样落盘。设置页里的「清空译文缓存与术语表」一并清掉。
- **抽术语不影响译文**：术语抽取在译文送达用户之后才发起，失败、超时、被中止都静默忽略，用户看不到任何异常；命中缓存的段落不会重复抽取；抽取有独立的并发上限（2），挤不进去就跳过，不占翻译的名额。
- **超时保护**：30 秒内没有任何响应（含流式中途卡住）会中止并提示重试。
- **错误提示说人话**：401 → 密钥无效、404 → 接口地址或模型不存在、连不上 → 检查网络和 Base URL，后面再附服务端原文。错误气泡里带「重试」按钮；没配密钥时带「去设置」按钮。
- **关闭思考**：按 Base URL / 模型名自动下发对应服务商的「禁用思考」参数，端点不认就按上面的三档降级自动去掉并记住。
- **并发上限 10**：同时进行的翻译请求最多 10 个（命中缓存不占名额，请求结束或被中止立即归还）。
- **气泡宿主样式用 `!important` 钉死**：有的站点（如 Jira）带 `!important` 规则会命中顶层 `div`，把宿主变成 `display:none`；宿主一旦不渲染，shadow 里的气泡连布局盒都没有，`visibility` 还会继承进去——表现就是「段落翻译正常、划词气泡永远不出现」。行内 `!important` 压得住页面的 `!important`，所以 `all:initial` 等关键属性一律加 `!important`。

## 安装

1. 打开 `chrome://extensions`，右上角开启「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择本目录。
3. 首次安装会自动打开设置页，填写接口地址 / 密钥 / 模型，点「测试连接」——成功会显示耗时和一句样例译文（绿色），失败会显示原始错误（红色）。

## 配置

每个 profile 独有：

| 项 | 说明 | 示例 |
| --- | --- | --- |
| 配置名称 | 只用于下拉框里区分，改它就是重命名 | `DeepSeek`、`本地 Qwen` |
| Base URL | OpenAI 兼容端点，插件会追加 `/chat/completions` | `https://api.openai.com/v1`、`https://api.deepseek.com/v1`、`http://localhost:11434/v1` |
| API Key | Bearer Token | `sk-...` |
| 模型 | 下拉选择。填好 Base URL 和密钥后自动 `GET /models` 拉列表（嵌入、语音、画图等模型已过滤），↻ 重新获取；端点没有这个接口或列表不全时选「手动输入…」自己填 | `gpt-4o-mini`、`deepseek-chat`、`qwen-plus` |
| 目标语言 | 翻译目标，中英日韩俄会用于「已是目标语言就跳过」的判断 | `简体中文` |
| 关闭模型思考 | 勾选后按下表自动下发禁用思考参数 | 默认开启 |
| 长段落译完后抽取术语 | 维护跨段落术语表，每个长段落多花一次很短的请求；查词和短译文入表不受此开关影响 | 默认开启 |
| 额外请求参数 | 合并进请求体的 JSON，用于覆盖上面的自动判断 | `{"reasoning_effort":"none"}` |

所有 profile 共用：

| 项 | 说明 | 示例 |
| --- | --- | --- |
| 触发键 | Ctrl / Alt / Shift（选 Shift 时注意和中文输入法切换冲突） | `Ctrl` |
| 在本站启用 | 按域名停用，仅在从工具栏图标打开时显示 | — |

### 「关闭思考」自动匹配规则

| Base URL / 模型 命中 | 下发参数 |
| --- | --- |
| `openrouter` | `{"reasoning":{"enabled":false}}` |
| `localhost` / `127.0.0.1` / `ollama` / `vllm` / `lmstudio` | `{"think":false,"chat_template_kwargs":{"enable_thinking":false}}` |
| `qwen` / `dashscope` / `aliyuncs` | `{"enable_thinking":false}` |
| `glm` / `zhipu` / `bigmodel` / `kimi` / `moonshot` / `minimax` | `{"thinking":{"type":"disabled"}}` |
| `gpt-5.1+` | `{"reasoning_effort":"none"}` |
| `gpt-5` / `o1`–`o9` / `grok` | `{"reasoning_effort":"minimal"}` |
| 其他（如 `gpt-4o`、`deepseek-chat`、`claude-*`） | 不传（这些模型默认就不思考） |

匹配不准时，在「额外请求参数」里手填即可覆盖。

配置保存在 `chrome.storage.local`（仅本机，不会同步到 Google 账号）：`profiles` 是全部配置的数组，`activeProfileId` 指向当前生效的那一套。从 1.1 及更早版本升级上来时，原有的扁平配置会自动变成名为「默认」的第一个 profile，不用重新填。

## 测试

段落结构靠「编码成占位标记 → 模型 → 还原成节点」这条往返链路，链路上任何一环被静默改坏，表现都是「译文粘成一坨」或「标签当正文显示出来」。两套测试各守一半：

```bash
node --test tools/test.js
```

纯逻辑部分（无需浏览器）：render 对模型输出的容错——标记被写成 `<br/>`、`</n4>`、`<n4 >`、多一个尖括号、编号乱编、大小写不对、干脆全丢时，还原出的分段必须完全一致，且正文里的 `5 < 6`、`List<T1>` 不能被误当标记吃掉；流式传到一半的半截标记不能露出来；长段落分片不能切坏占位标记、拼回去要与原文一字不差；提示词里的关键约束（标记规则、禁止改写成 HTML）不能被误删。

浏览器部分：在 Chrome 里直接打开 `tools/test.html`（标题栏显示 `PASS n / n`）。`encodeInline` 的判断全部来自排版引擎——元素是不是块级看 computed `display`、换行是不是内容看 `white-space`、flex 子项的 `display` 还会被强制成 `block`——node 里的 DOM 桩模拟不出这些。用例覆盖 X 推文（`pre-wrap` 文本节点里的 `\n` 分段 + `@某人` 的 flex 壳）、评论区的 `<br><br>`、文章的 `<p>`/`<ul>`、行内链接与代码图片、表格、隐藏元素、已插入的译文、`<pre>` 代码块，每个用例都断言**送给模型的原文与预期逐字相符**，再把它按十种「模型写歪」的姿势弄歪一遍，要求还原出的排版与元素结构和原文一模一样。

## 已知限制

- 行内结构靠占位标记还原，**依赖模型把标记原样吐回来**。漏标记会自动重发一次，两次都漏时那一段退化为纯文本（文字完整，只丢链接和加粗）；标记编号乱编时该标记被忽略。小模型上出错概率更高。
- 页面若用 `#id` 或 `:nth-child` 一类选择器给段落设样式，译文节点匹配不到这些规则（id 不能重复），显示会有差异。用 class / 标签 / 内联样式的情况（绝大多数页面）完全一致。
- 长段落分片是**串行**的，分片之间只传递前一片译文的结尾，不做全段两遍精修，所以跨分片的长距离指代仍可能不一致。
- 术语表只在**术语已经入表之后**生效：一段文字里首次出现的生僻词仍由模型自行决定译法，要等它进表才会约束后面的段落。因此同一页面**从前往后**读的一致性最好。
- 译文缓存**不含术语表**：某段在术语入表前已经译过并缓存，再翻它会直接返回旧译文，不会用上新术语。清空缓存可让它重译。
- 发音用的是 `translate.google.com` 的**非官方**端点（不需要 key）：可能限流（返回 429），也可能哪天就改掉；文本上限约 200 字符，所以只给词和短语。语种由脚本判断，只支持 zh / en / ja / ko / ru，认不出语种时不显示喇叭图标。选中的词本身已是目标语言时走「已经是…」的提示路径，不出气泡，也就没有发音按钮。
- 术语表按站点存，**不区分同一站点下的不同页面**。这对文档站是优点（整站统一），对内容互不相关的大站（如资讯聚合站）会攒下一些用不上的条目——它们只在原文里真的出现时才注入，所以不会白花 token。

| `content.js` | 触发键监听、页面背景采集、行内结构编解码、气泡渲染与定位、段落译文插入 |
| `offscreen.html/js` | 发音的播放端：取音频并播放，不受宿主页面 CSP 影响，空闲即自关 |
| `options.html/js` | 设置页 / profile 管理（同时作为工具栏弹窗） |
| `icons/` | 扩展图标 |
| `tools/test.js` | 纯逻辑测试：`node --test tools/test.js` |
| `tools/test.html` | 结构编解码测试：浏览器里打开，标题栏显示 `PASS n / n` |
| `tools/harness.js` | 测试用的加载器：把源文件原样跑进 vm 上下文，附最小 DOM |
